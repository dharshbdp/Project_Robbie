# Basic conversation first

The objective for this experiment is coherent everyday conversation: a relevant
short reply, sensible use of the previous exchange, and a clean end to the reply.
It keeps Robbie's own 26.5M transformer and frozen BPE vocabulary. It adds no
question-specific inference rules or downloaded model weights.

This is a narrower, controlled curriculum after the unsuccessful broad chat v1
run. Its effectiveness must be established from generated replies after training.
Preparation and a forward/backward check are setup checks, not quality evidence.

## Data and format

The prepared data contains **4,527 training answer examples, 217 validation
examples, and 226 reserved test examples**. It uses the everyday-conversation
subset of the already downloaded, pinned
[SmolTalk data](https://huggingface.co/datasets/HuggingFaceTB/smol-smoltalk), plus
20 authored seed conversations (26 answer examples) for Robbie's identity,
clarification, and simple context use. The main dataset is synthetic; the seeds
are a small authored supplement, not a broad knowledge corpus.

Preparation preserves entire turns, limits each turn to 40 words and assistant
content to 128 BPE tokens, and rejects code blocks, oversized turns, and excessive
unknown tokens. It normalizes curly quotation marks and similar punctuation.
Conversations with an invalid turn are rejected as a whole. Previous exchanges
can be pruned only under the shared context-fit rule; the latest preceding
exchange is retained for follow-ups. Complete answers that cannot fit are skipped.

Groups use the first substantive user question. Shared greeting starters are
retained as context but excluded as validation/test targets. This prevents
unrelated conversations starting with "Hi" from landing in one large split and
keeps memorized greeting targets out of the reported held-out loss. Exact topic
prompt grouping does not establish semantic novelty of all held-out examples.

Training and direct chat share the same formatter: each past assistant turn
ends with the **actual EOS token ID**, not the printed token name. The checkpoint
records this format, and old checkpoints retain their original format when
loaded. Consistent chat formatting is also described in the
[Transformers chat-template guide](https://huggingface.co/docs/transformers/chat_templating).

## Train in PowerShell

```powershell
Set-Location 'Z:\Project_Robbie\Project_Robbie'
.\.venv\Scripts\python.exe -u scripts\train_clean_chat.py
```

The command runs two stages from the original stage-1 base:

1. **Language, 8 epochs:** next-token loss on the complete short dialogue examples,
   including user turns and previous answer endings. This adapts the narrow
   base to the conversation format; it is not large-scale general pretraining.
2. **Replies, 8 epochs:** initialize from the language stage's lowest-validation-loss
   checkpoint, then supervise assistant answers and EOS only.

Defaults use context 512, microbatch 8, accumulation 4, BF16 on the RTX 4060,
peak learning rates 0.0002 then 0.0001, warmup and cosine decay. Progress prints
every 5 updates; checkpoints save every 50; generated basic-chat examples and
validation run every 100 updates and at epoch ends. Sample follow-ups use the
model's own earlier answers. Their prompts are development checks, not an
independent benchmark. Reports record repetition and whether generation reaches
EOS before the token limit, and still require review for relevance and correctness.

The stage directories are `checkpoints/clean_chat_v1/language` and
`checkpoints/clean_chat_v1/replies`. Original checkpoints and chat v1 are preserved.

Press **Ctrl+C once**, then wait for the current update to save. The next stage
will not start after a pause. To resume, run the **same command**. It resumes an
unfinished stage and skips completed stages. Saved optimizer settings are restored;
use a new `--output-dir` to change the experiment. Dataset files must remain
unchanged for resume.

To train only one stage, use `--stage language` or `--stage replies`. Reply training
requires a completed language stage. An interrupted or failed stage never triggers
the next one.

## Review the candidate

```powershell
.\.venv\Scripts\python.exe scripts\chat_model.py --checkpoint checkpoints\clean_chat_v1\replies\best_chat.pt
```

Try greetings, ordinary questions, changing a preference in a follow-up, and
asking for a shorter explanation. `/clear` starts a fresh conversation. Every
reply in this command is generated by the model. Use it to judge the new candidate
explicitly before selecting it for the editor.

After reviewing development replies, run the reserved test evaluation once:

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_chat.py --checkpoint checkpoints\clean_chat_v1\replies\best_chat.pt --data-dir data\processed\clean_chat_v1\answers --profile basic
```

A low loss or a passed structure check does not establish a usable chatbot.
Review its actual relevance, coherence, follow-up understanding, and stopping.
Do not repeatedly tune against the reserved test split.

## Reproduce setup

```powershell
.\.venv\Scripts\python.exe -u scripts\prepare_clean_chat.py
.\.venv\Scripts\python.exe -u scripts\train_clean_chat.py --dry-run
```

Preparation expects the four pinned SmolTalk shards downloaded by the earlier
`prepare_chat.py` setup. It refuses to overwrite a completed curriculum. Both
objectives passed a full-length 8-by-512 CUDA forward/backward check without
optimizer updates or saved model weights; peak allocated VRAM was 0.87 GB.
This measured allocation excludes display/other applications and is not a promise
of final optimizer memory use or model quality.
